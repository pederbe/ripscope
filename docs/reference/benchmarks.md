# Benchmarks

The search-time tables below come from the **18 and 19 October 2026** measurement of the
0.1.0 release candidate, Ripscope revision `2fdce59`. The Linux kernel selection comes
first, followed by Redis and zlib. Both repetitions and both platforms are shown
separately, and every time and comparison note comes from that measurement.

With updates skipped, Ripscope wins 30 of the 50 later searches against cscope `-q`
on Linux and 47 of 50 on Windows, in both repetitions. Against plain cscope the
counts are 48 and 49. A win needs a clear timing difference and an equivalent or
source-confirmed better answer.

After a normal startup a Ripscope Session watches its sources and refreshes on its
own. On Linux that costs nothing measurable per search. On Windows each search
first checks a marker file, about 0.3 to 0.5 ms, so cscope `-q` answers the three
lookups of a name nobody defines faster there, and Ripscope wins the other 47.

## Search times

Times are **milliseconds**. First means a query's first pass after Session
startup, after any preceding queries. Later means a subsequent pass within that
Session. Search times exclude Session startup. “Normal startup” includes each
tool's own freshness checks before the Session becomes ready. “Updates skipped”
opens existing indexes without those checks.

## Conditions and interpretation

- **Linux** uses native executables on an Intel i7-8550U, warm tmpfs source and
  indexes, and Ubuntu cscope 15.9-2build1.
- **Windows** uses native executables in a Windows 11 virtual machine with two
  virtual CPUs, warm NTFS source and indexes, and MSYS2 cscope 15.9-3 with
  `MSYS=noglob`. The platforms run on different hosts with different cscope builds,
  so compare the tools within a platform rather than across platforms.
- Both configurations use release builds. Each Session measurement has 32
  observations per repetition. A clear timing result needs at least ten
  observations, non-overlapping middle-half ranges and a median difference above
  that repetition's calibrated floor.
- No row is a clear win in one repetition and a clear loss in the other, though some
  rows are clear in one and inconclusive in the other. The Linux machine and the
  Windows host stayed quiet. The Windows guest monitor flagged background activity in
  43 of its 674 intervals in the first repetition and none in the second, and the
  later-search wins agree.
- The kernel selection has 3,579 files, Redis 172 and zlib 26. It is a sparse
  selection of the kernel, not the whole kernel. Source revisions, ordered inventory
  digests, queries and every timing are in the
  [measurement record](../../evidence/performance-20261019.json).
- Answers are assessed separately from time. A source-confirmed better answer counts
  as a win when it is also faster. The conditional-caller limitation and the faster
  cscope `-q` kernel symbol-pattern search show as tradeoffs. See
  [answer evidence](benchmark-answers.md).

The measured product revision is `2fdce5902704e6e573b1a6bcd7e57a7477136e71`. The
[limitations](limitations.md) describe recognition boundaries beyond these queries.
